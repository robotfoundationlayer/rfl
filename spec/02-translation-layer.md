# Translation Layer — Specification (skeleton)

> **Status**: pre-release skeleton. Full text targeted for v0.1 (2027 Q1).

## Scope

This chapter defines:

1. The canonical embodiment-agnostic action representation
2. The embodiment descriptor schema (`schemas/embodiment-descriptor.schema.json`)
3. The deterministic retargeting algorithm `retarget(skill, embodiment) -> canonical_actions`
4. The safety envelope semantics and how envelope constraints flow from Skill ISA into per-embodiment action parameters

## Canonical action representation (provisional)

A canonical action is a tuple:

```
CanonicalAction := (
    target_frame:   FrameRef,
    target_pose:    Pose6D,
    force_budget:   Option<Force[N]>,
    timing:         TimingHints,
    tactile_target: Option<TactileTarget>,
    safety_envelope: Envelope,
)
```

The full type definitions, including the `Envelope` algebra, will be specified before v0.1.

## Retargeting algorithm — determinism requirement

`retarget(skill, embodiment)` must be **deterministic**: identical inputs produce identical canonical-action sequences, byte-for-byte. The determinism requirement is binding because conformance testing (`05-conformance.md`) compares observed retargeting output against frozen fixtures.

## Open issues

- Pose representation choice (SE(3) matrix vs. quaternion + translation vs. axis-angle)
  - *Constraint surfaced during `reach.to_pose` design (2026-05-30)*: the Skill ISA expresses `orientation_tolerance` as a single geodesic angle on SO(3). Whichever pose representation is chosen must admit a single-scalar geodesic orientation error, so that `pose_not_reached` is mechanically decidable. Fix this before the representation is frozen.
- `controlled_frame` declaration responsibility (surfaced during `reach.to_pose` design, 2026-05-30): `reach` primitives parameterize the moved frame as `controlled_frame`, defaulting to `embodiment.default_control_frame`. Retargeting must map `controlled_frame → embodiment native frame`. Non-anthropomorphic embodiments may expose several control frames, so the embodiment descriptor (`schemas/embodiment-descriptor.schema.json`) needs a `control_frames` set and a `default_control_frame` field. Resolve before the descriptor schema is frozen.
- Rest-at-goal vs. trajectory blending (surfaced during `reach.to_pose` design, 2026-05-30): `reach.to_pose` v0.1 guarantees termination at rest, which keeps composition with `grasp`/`force` unambiguous. Efficient non-stop blending through a waypoint chain is a foreseeable extension; reserve design room (e.g. a future `stop_at_goal: bool`) so it can be added without breaking the rest-at-goal guarantee (Principle 5).
- `embodiment.default_tool_axis` descriptor field (surfaced during `reach.approach` design, 2026-05-30): `reach.approach`, `reach.align`, and the `force` family parameterize a working/approach axis defaulting to `embodiment.default_tool_axis`. The embodiment descriptor needs a per-control-frame tool-axis declaration. Resolve alongside the `control_frames` set above.
- Collision-model partitioning — clearance must exclude the approach target (surfaced during `reach.approach` design, 2026-05-30): `reach.approach` applies `clearance` against the static model **excluding** the object being approached, otherwise the approach is self-forbidding. The retargeting algorithm and the Driver Interface collision-model representation must both be able to designate a target subset that is exempt from clearance for the duration of a primitive. Non-trivial; resolve before the collision-model schema is frozen.
- `SurfaceTarget` type and the perception-scope boundary (surfaced during `reach.approach` design, 2026-05-30): `reach.approach` consumes a `point` + outward `normal`, both perception-derived. RFL deliberately does not define perception, so a `SurfaceTarget` must be supplied as an already-resolved frame — typically the result of `sense.locate` hoisted through `LetBind`. The `SurfaceTarget` type definition (point, unit normal, frame, uncertainty bound) is owned by the Skill ISA; the perception that produces it is out of scope.
- Swept-volume clearance queries (surfaced during `reach.align` design, 2026-05-30): `reach.to_pose` and `reach.approach` check clearance over a straight-line corridor, but `reach.align` rotates in place and must check clearance over the rotation's **swept volume**. The Driver Interface collision-model representation must support a swept-volume clearance query, not only point/corridor queries. Resolve before the collision-model schema is frozen.
- Under-constrained-orientation residual rule — consistency (decided during `reach.align` design, 2026-05-30): when an orientation constraint leaves a residual rotational DOF (single-axis `reach.align`; the free normal-axis rotation of `reach.approach`), the residual is resolved as the **minimum geodesic rotation from the current orientation**. This rule is now decided and binding for `retarget` determinism; it must be applied uniformly wherever orientation is under-constrained across the spec, not re-litigated per primitive.
- Maintained-invariant conformance methodology (surfaced during `reach.hover` design, 2026-05-30; owned by `05-conformance.md`): terminal-postcondition primitives (`reach.to_pose`, `reach.approach`, `reach.align`) are verifiable by endpoint check, but sustained primitives (`reach.hover`, and later `force.wipe`/`force.scrub`) hold an invariant over an interval and require **interval sampling**. The conformance suite needs an "interval-invariant" test class distinct from the endpoint classes.
- `reactive`-body envelope precedence (surfaced during `reach.hover` design, 2026-05-30; owned by `01-skill-isa.md` BNF note 1): when `hover` is the body of `reactive(hover, until(pred))` and an envelope violation coincides with the `until` predicate firing, the safety-abort must take precedence over clean predicate termination. Fix this ordering when the `reactive` `until` semantics are formalized.
- `embodiment.limits.tracking_bandwidth` descriptor field (surfaced during `reach.hover` design, 2026-05-30): `reach.hover(track_target = true)` requires the embodiment to declare its target-tracking bandwidth so the precondition and `track_lost` failure mode are decidable. Add to `embodiment.limits`.
- `ScanRegion` type definition (surfaced during `reach.scan` design, 2026-05-30; owned by `01-skill-isa.md`): `reach.scan` consumes a region geometry (volume / surface / path). This is a task-specified, not perception-derived, type and belongs to the Skill ISA type system. Define before scan reaches freeze.
- Visual/range sensor descriptor fields (surfaced during `reach.scan` design, 2026-05-30; owned by `03-driver-interface.md`): scan needs `embodiment.default_sensor_frame` and per-sensor `fov`, `bore_axis`, and `max_sweep_rate`. The existing descriptor covers tactile sensor placement; generalize it to visual/range sensors so the `auto` overlap and motion-blur velocity cap are decidable.
- Normative sweep-pattern generators (surfaced during `reach.scan` design, 2026-05-30): the `Σ` sweep-pose set for `pattern ∈ {raster, spiral, arc, waypoints}` must be a deterministic, algorithmically specified function of `(region, pattern, standoff, overlap, FOV)` so that `retarget` determinism and cross-implementation conformance (`reach.scan` C2) hold. Specify the generators in a normative appendix.
- Start-in-contact + break-contact envelope pattern (surfaced during `reach.retract` design, 2026-05-30): `reach.retract` is the first primitive where starting in contact is legal and the goal is to *leave* contact, enforced by a `break_contact` postcondition plus a **directional force-monotonicity** envelope (force increasing along the retreat direction = collision = abort; force decaying = the surface being left = fine). This pattern recurs in `grasp.release` and `place.put_down`; specify it once as a reusable envelope clause rather than re-deriving per primitive. No new descriptor field required (`default_tool_axis` suffices).
- `ObjectTarget` type definition (surfaced during `grasp.pinch` design, 2026-05-30; owned by `01-skill-isa.md`): `grasp.pinch` consumes geometry + pose + **material / mass / fragility** — richer than `SurfaceTarget`, because force budgeting and crush protection depend on it. Perception-derived parts arrive via `LetBind`; the type itself belongs to the Skill ISA type system.
- Grasp descriptor fields (surfaced during `grasp.pinch` design, 2026-05-30; owned by `03-driver-interface.md`): `embodiment.default_grasp_frame`, `embodiment.grasp_envelope`, capability flag `pinch_grasp`, and limits `payload_grasp_pinch` / `grip_force_max` / `v_grasp`. Generalize the capability manifest to carry grasp capabilities and per-grasp payload/force limits.
- Tactile-absent confirmation proxy (surfaced during `grasp.pinch` design, 2026-05-30; owned by `04-tactile-manifold.md`, Principle 5): when an embodiment does not declare `tactile_sensing`, "force closure achieved" must still be confirmable via a force/position proxy. Specify the graceful-degradation proxy so non-tactile embodiments can run `grasp.pinch` (and the rest of `grasp`) without falsely reporting success.
- Force-closure mechanical verification (surfaced during `grasp.pinch` design, 2026-05-30; owned by `05-conformance.md`): "grip force reached budget" ≠ "stable grasp". Canonicalize the **hold test** (apply a calibrated sub-budget perturbation, require retention) as the operational, mechanically checkable definition of force closure for all `grasp` primitives.
- Enclosure-grasp descriptor fields (surfaced during `grasp.power` design, 2026-05-30; owned by `03-driver-interface.md`): `embodiment.limits.enclosure_span`, `embodiment.limits.payload_grasp_power`, capability flag `power_grasp`. Concrete instance of the per-grasp-mode payload/force-limit pattern noted under the grasp descriptor issue above.
- "Grasp core" abstraction — spec structuring (surfaced during `grasp.power` design, 2026-05-30; owned by `01-skill-isa.md`): all ten `grasp` primitives share a core (`target`, `force_budget`, `grasp_pose`, tactile confirmation, capability requirement, hold-test verification) and differ only in a **contact-pattern abstraction** (antipodal pair / whole-volume enclosure / hook / tripod / lateral / …). Define the core once at the head of Category 2 and reduce each primitive to "core + contact-pattern delta"; planned as a post-category refactor to avoid churning already-frozen `grasp.pinch`/`grasp.power` text mid-review.
- Hold-test branching by closure type (surfaced during `grasp.hook` design, 2026-05-30; owned by `05-conformance.md`): the grasp-core hold test assumes force closure (omnidirectional perturbation). `grasp.hook` is form closure (perturbation only along `load_direction`). The hold-test definition must branch on `closure ∈ {force, form}`. Refines the hold-test canonicalization noted above.
- Grasp stability metadata in the result schema (surfaced during `grasp.hook` design, 2026-05-30; owned by `01-skill-isa.md`): grasp results must carry `closure ∈ {force, form}` and `stable_directions`, so `transport`/`in_hand` respect a directional grasp's stability envelope. Apply retroactively to `grasp.pinch`/`grasp.power` (`closure = force, stable_directions = omnidirectional`) during the grasp-core refactor.
- `FeatureRef` and the target type hierarchy (surfaced during `grasp.hook` design, 2026-05-30; owned by `01-skill-isa.md`): `ObjectTarget` must expose sub-features (handle/loop/bar) as `FeatureRef`. Organize the `SurfaceTarget → ObjectTarget → FeatureRef` type hierarchy in the Skill ISA type system.
- Hook-grasp descriptor fields (surfaced during `grasp.hook` design, 2026-05-30; owned by `03-driver-interface.md`): capability flag `hook_grasp`, `embodiment.limits.hook_load_capacity`.
- Tripod-grasp descriptor fields (surfaced during `grasp.precision_tripod` design, 2026-05-30; owned by `03-driver-interface.md`): capability flag `tripod_grasp`, `embodiment.limits.payload_grasp_tripod`, `embodiment.limits.precision_object_size_max`.
- `rotation_constrained` result metadata (surfaced during `grasp.precision_tripod` design, 2026-05-30; owned by `01-skill-isa.md`): a grasp result carries `rotation_constrained: bool` so `in_hand.rotate` knows whether the grasp permits spinning the object. Fold into the grasp stability-metadata set (`closure`, `stable_directions`) during the grasp-core refactor.
- Non-degenerate-triangle geometric confirmation (surfaced during `grasp.precision_tripod` design, 2026-05-30; owned by `05-conformance.md`): define the threshold (non-collinearity / minimum triangle area) by which the conformance suite mechanically decides a tripod's 3 contacts are non-degenerate.
- Lateral-grasp descriptor fields (surfaced during `grasp.lateral` design, 2026-05-30; owned by `03-driver-interface.md`): capability flag `lateral_grasp`, `embodiment.limits.lateral_grasp_max_thickness`, `embodiment.limits.payload_grasp_lateral`.
- Stability-metadata generalization — form-held vs friction-held DOF (surfaced during `grasp.lateral` design, 2026-05-30; owned by `01-skill-isa.md`): `grasp.hook` (directional, form-held) and `grasp.lateral` (in-plane friction-held) show that `stable_directions` cannot be a flat direction set. It must distinguish **form-held DOF** (geometrically secured) from **friction-held DOF** (secured only up to a friction limit dependent on force and load). Core design decision for the grasp-core refactor; `transport`/`in_hand` consume it to choose conservative motion.
- Bend / crease tactile indicator (surfaced during `grasp.lateral` design, 2026-05-30; owned by `04-tactile-manifold.md`): thin-object bending is a distinct failure axis from crush (compression). Define a bending-indicator feature in the TactileManifold field set.
- Third closure type `support` (surfaced during `grasp.platform` design, 2026-05-30; owned by `01-skill-isa.md`): `closure ∈ {force, form, support}`. The stability-metadata generalization must add a **balance-held / CoM-over-polygon** category alongside form-held and friction-held. Core design decision for the grasp-core refactor.
- `ObjectTarget` center-of-mass extension (surfaced during `grasp.platform` design, 2026-05-30; owned by `01-skill-isa.md`): `grasp.platform` static-stability requires a CoM estimate. Extend `ObjectTarget` with `center_of_mass` alongside `estimated_mass`.
- Platform-support descriptor fields (surfaced during `grasp.platform` design, 2026-05-30; owned by `03-driver-interface.md`): capability flag `platform_support`, `embodiment.default_support_frame`, support-contact-polygon geometry, `embodiment.limits.payload_support`.
- Support-grasp safe-state semantics (surfaced during `grasp.platform` design, 2026-05-30; owned by `05-conformance.md` safety class): a closure grasp returns to safety by opening, but a balanced (support) object cannot — the safe state is "lower to the nearest surface, minimize fall height." Define this support-specific safe state in the safety conformance class.
- Extrinsic / surface-bound grasp flags (surfaced during `grasp.pin` design, 2026-05-30; owned by `01-skill-isa.md`): `grasp.pin` is force closure mediated by an environment surface. Rather than a fourth closure type, carry `extrinsic: bool` and `surface_bound: bool` flags in the grasp stability metadata. Keeps `closure ∈ {force, form, support}` from proliferating.
- Composition validity by grasp stability class (surfaced during `grasp.pin` design, 2026-05-30; owned by `01-skill-isa.md` algebra / `05-conformance.md` composition class): a `surface_bound = true` grasp must not be followed by a free-transport primitive — doing so loses the surface. The algebra needs a "grasp stability class → permitted successor primitives" constraint table, checked at validation. Design alongside the grasp-core refactor and the `reactive`/composition formalization.
- Pin-grasp descriptor field (surfaced during `grasp.pin` design, 2026-05-30; owned by `03-driver-interface.md`): capability flag `pin_grasp` (minimal — a single force-controlled contact).
- Caging residual-mobility metadata (surfaced during `grasp.envelope` design, 2026-05-30; owned by `01-skill-isa.md`): add `residual_mobility` and `compliant` flags under the form-held stability category — a caged object is retained ("cannot escape") yet not fixed. `transport` consumes `residual_mobility` to account for in-cage shifting.
- Uncertainty-robustness in capability negotiation (surfaced during `grasp.envelope` design, 2026-05-30; owned by `02`/`03`): `grasp.envelope` tolerates geometric uncertainty by design. Capability negotiation should route uncertain-geometry tasks to envelope-capable embodiments, using the grasp's declared uncertainty-robustness.
- Envelope-grasp descriptor fields (surfaced during `grasp.envelope` design, 2026-05-30; owned by `03-driver-interface.md`): capability flag `envelope_grasp`, `embodiment.limits.payload_grasp_envelope`, cage geometry / enclosure range.
- Grasp-continuity envelope class (surfaced during `grasp.adjust` design, 2026-05-30; owned by `05-conformance.md`): a third envelope class after reach's terminal-postcondition and hover's maintained-invariant — the held → held continuity invariant "holding force never drops below `min_holding_force`." Define it as a conformance test class verified from the force trace.
- Active-grasp state model and `GraspRef` (surfaced during `grasp.adjust` design, 2026-05-30; owned by `01-skill-isa.md`, foundational): the Skill ISA needs a per-`controlled_frame` "active grasp" state and a `GraspRef` type, so `grasp.adjust` / `in_hand.*` / `transport.*` / `place.*` reference an established grasp. Define the grasp lifecycle (free → held → manipulated → placed → free) as Skill ISA state. This underpins the Category 2 ↔ 3/4/5 connection.
- `min_holding_force` derivation (surfaced during `grasp.adjust` design, 2026-05-30; owned by `02`): the force below which the object drops, derived deterministically from `target` mass, grasp mode, friction, and load direction. Required for `grasp.adjust` and `transport` safety.
- Supported-state predicate (surfaced during `grasp.release` design, 2026-05-30; owned by `01-skill-isa.md` world-state / `02`): `grasp.release` (and the `place` family) need a world-state predicate "the object is stably supported" — resting on a surface with CoM inside its own support polygon — to decide whether releasing is safe. Define this predicate; it reuses the CoM-over-polygon logic from `grasp.platform`.
- Tactile-target representation under TactileManifold (see `04-tactile-manifold.md`)
- Time-scaling semantics under embodiment kinematic limits
